• Type: Test Case | Priority: Highest | Labels: e2e, negative, resilience, idempotency, cobro-ordenes
  • Preconditions: The POST endpoint is mocked to return HTTP 500 after a 1.5 s delay. A request counter is attached.
  • Steps:
    1. Navigate to /cobro_ordenes.
    2. Upload evil.csv.exe (binary content, application/octet-stream).
    3. Upload junk.csv containing:
      • an empty order number
      • an unknown store (XXXX)
      • a 10,000-character order number
      • an SQL-injection string ('; DROP TABLE x;--)
    4. Double-click "Subir y Procesar".
    5. Wait for the response.
  • Expected Result:
    • The non-CSV file is rejected client-side and "Subir y Procesar" stays disabled.
    • The double-click sends at most one POST request (no duplicate charge).
    • An error toast or alert is shown to the user.
    • The button returns to the enabled state with no stuck spinner.
    • No Next.js "Application error" crash screen appears.
  • Pipeline gate: Blocker.
  • Note: A duplicate POST is a potential double-charge defect. Raise it as Severity 1.
