Hydra Command Reference

Every hydra command, what it does and its flags. Run them from HydraLabs/testengine with go run ./cmd/hydra <command>, or with the built binary. Hydra loads your secrets from ~/.hydra.env and HydraLabs/.hydra.env on its own.

Common flags

--project KEY
A project registered in projects.json, e.g. DWQ. Most commands need one, or they run for every registered project.
--registry FILE
Path to projects.json. Found automatically in the default location.
--profile FILE
A profile file for one app, used without a registry (the older single-app layout).

Use it day to day

hydra board

One page with every view of a project side by side, and buttons for each action. Start here.

hydra board --project DWQ [--addr 127.0.0.1:8090]
--addr
Where to serve the page. Localhost only by default.

Buttons: Crawl, Poll, Deliver, Automate or Execute one case, and Stop the running action.

hydra cases

A local page to write the app's test cases into cases/<KEY>.md, which you commit. No repository editing needed.

hydra cases --project DWQ [--addr 127.0.0.1:8098]

hydra watch

Read-only live view of every stage the app's runs go through. Changes nothing.

hydra watch --project DWQ [--addr :8099]

hydra run

Routes one case through the pipeline: automate or execute it, and record the result. Use --html to ingest a rendered description first.

hydra run --project DWQ --key DWQ-132 [--intent automate|execute] [--html FILE] [--summary TEXT]

hydra automate <CASE-KEY>

Build the automated test for one case from its Jira text, then run it against the app. The project is found from the key prefix, so --project is optional.

hydra automate DWQ-L1 [--project DWQ]

hydra execute <CASE-KEY>

Run a case's test as it is already built, using the test repo's data. Nothing is generated.

hydra execute DWQ-L1 [--project DWQ]

hydra poll

Look at Jira issues labeled automate or execute and process each one. Without --project, it polls every registered project.

hydra poll [--project DWQ] [--only DWQ-139] [--intent automate|execute] [--force] [--comment] [--jql QUERY] [--json] [--model-cases N]
--only KEY
Process just this issue, e.g. for a manual trigger.
--intent
With --only: treat the issue as automate or execute even without the label.
--force
Run again even if the issue was already seen.
--comment
Post outcomes that need a person to the Jira issue. Off by default until results are trusted.
--jql
Which issues to look at. Default: issues labeled automate or execute.
--json
One JSON object per run, for n8n or scripts.
--model-cases
Cases allowed to use the model per poll. The rest wait for the next poll.

hydra deliver

Run each passing case several times in the real framework, then commit the ones that passed every run on a local review branch in the app's repo. Nothing is pushed or merged.

hydra deliver --project DWQ [--only DWQ-130,DWQ-131] [--exclude KEY,...] [--repo PATH] [--runs 3]
--only / --exclude
Comma-separated case keys to include or leave out.
--runs
Consecutive passes a case needs. Default 3. A flaky case blocks the whole delivery.
--repo
The framework repo that receives the tests.

A case that writes data writes once per run, so use a QA environment that can take it.

Set up and check

hydra init

Set up a new team by answering questions one at a time. Nothing is written until you confirm at the end.

hydra init [--answers team.json] [--yes] [--no-preview]
--answers FILE
Answers in a file, for CI. Questions covered by the file are not asked.
--yes
No prompts. Missing answers take their defaults.
--no-preview
Skip the one-page preview crawl.

hydra onboard

Create the Hydra-<App> repository for a registered project, if it does not exist yet. A second run changes nothing.

hydra onboard --project DWQ

Exits with code 3 if a setting is still missing (for example the app URL).

hydra status

Read-only, no Jira calls. Shows the state of every tracked project.

hydra status [--json]

hydra history

Read-only list of past executions for a project, or for one case.

hydra history --project DWQ [--key DWQ-132] [--last 30] [--json]
--last
Show the newest N. Use 0 for all.

Crawl, design and announce

hydra crawl

Visit the app, record its pages and elements, and find the best locator for each. Needs the labs add-on enabled for the project.

hydra crawl --project DWQ [--watch :8099] [--headed] [--store] [--video] [--slow MS]
--store
Save the crawl in the app's repo, on a review branch.
--watch
Serve a live view of the crawl at this address.
--headed / --video / --slow
Show the browser, record a video, or slow each step down for demos.

hydra design

Draft test cases from a requirement. Drafts go to Jira only after you review them and confirm.

hydra design --project DWQ --from requirement.txt [--max 3] hydra design --project DWQ --story DWQ-129 [--max 3] hydra design --project DWQ --create last --parent DWQ-129 [--type Task] [--yes]
--from / --story
The requirement, as a text file or as a Jira story key.
--max
The most cases to draft. Default 3.
--create
Create the drafts that passed in a saved run (a folder, or last) in Jira, under --parent. Asks first unless --yes.

hydra announce

Backfill: post Jira comments on cases delivered before write-back existed. Dry run by default.

hydra announce --project DWQ [--keys DWQ-1,DWQ-2] [--post]

Without --post, it only prints what would be posted.

Playlists (new, script only)

playlist.py check / run

Run an ordered flow of ready cases where later steps use values captured earlier, such as an order number. This is a separate script, not yet a hydra command. See testengine/PLAYLISTS.md.

python3 tools/jira/playlist.py check --playlist flow.json --cases cases.json --out automation python3 tools/jira/playlist.py run --playlist flow.json --cases cases.json --out automation --base-url http://host:3000 [--allow-writes] [--record out/playlist.json]

Exit codes

CodeMeaning
0Done. A passing run also exits 0.
1An error, or a test run failed.
2Wrong usage: a missing argument or flag.
3The pipeline stopped and needs a person (for example poll, deliver or onboard waiting on a decision).

Not sure where to start? Run hydra board --project KEY and use the buttons.
